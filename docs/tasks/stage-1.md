Задание для Cline: создание проекта PromptFlow
Контекст
Ты работаешь над созданием учебного Flask-проекта PromptFlow — веб-приложения для организации производства AI-контента (видео, изображений, анимации). Проект должен быть небольшим, законченным MVP, пригодным для публичного GitHub-репозитория и портфолио.

Перед началом работы прочитай файл AGENTS.md полностью — это главный документ с контекстом, правилами и требованиями. Все решения должны соответствовать ему.

Что нужно сделать
Создать с нуля Flask-приложение PromptFlow согласно этапам разработки из раздела 13 AGENTS.md. Начать с Этапа 1 (Основа) и двигаться последовательно, небольшими логически завершёнными изменениями.

Flask application factory

app/__init__.py с create_app(config_name=None).

app/extensions.py с инициализацией db, migrate, login_manager, csrf.

Конфигурация через переменные окружения: development, testing, production (раздел 11).

Страница /health, возвращающая простой JSON {"status": "ok"}.

Конфигурация

.env.example с безопасными примерами: FLASK_APP, FLASK_ENV, SECRET_KEY, DATABASE_URL, POSTGRES_*.

Загрузка через python-dotenv (добавить в requirements.txt).

Секретный ключ только из окружения, никаких дефолтных секретов в коде.

Зависимости и настройки

requirements.txt с зафиксированными версиями (актуальными на момент установки).

pyproject.toml с конфигурацией Ruff (line-length 100, target py311) и pytest.

Docker

Dockerfile (Python slim, установка зависимостей, запуск через gunicorn или flask run).

compose.yaml с двумя сервисами: web (Flask) и db (PostgreSQL 16).

tests/conftest.py с фикстурой app (конфиг testing), client, db.

GitHub Actions

.github/workflows/ci.yml: установка зависимостей, запуск Ruff, запуск pytest на push и pull_request.

Правила работы
Соблюдай раздел 3 и 16 AGENTS.md:

Перед изменениями: изучи структуру, сформулируй короткий план.

Небольшие изменения: один логически завершённый шаг за раз.

Не удаляй работающую функциональность, не добавляй зависимости «на будущее».

Не выполняй git commit / git push без прямого запроса.

Не помещай секреты, пароли, токены в код, тесты, README.

Не утверждай, что тесты прошли, если не запускал.

Не скрывай ограничения среды выполнения.

Если требование неоднозначно и влияет на архитектуру — задай один конкретный уточняющий вопрос. В остальных случаях выбирай простейший безопасный вариант и явно обозначай допущение.

После каждого шага
Запусти pytest — все тесты должны проходить.

Запусти ruff check . — без ошибок.

Проверь git status / git diff — нет случайных правок и секретов.
